## Scope

Implemented `src/pic_utils/runner/service.py` (architecture §8.7):

- `RunnerSettings` (workers, memory ceiling, experiment timeout) and
  `RunRequest` (pipeline, snapshot, sources, second, run config, results
  root, settings, user-blocks folder), `RunSummary`.
- `RunService(QObject)`: `run_started`/`progress`/`result_ready`/
  `run_finished`/`run_failed`/`memory_updated` signals; `start()` runs the
  §8.7 sequence on a dedicated thread (validate → run folder + manifest →
  blocks copy → source load + shared memory → plan → dispatch → collect →
  finalize); `cancel(force)`; `is_running`; one run at a time (a second
  `start()` is a programming error).
- Source errors surface as issues, not crashes: unreadable sources are
  skipped with a warning (`skipped_sources` in the manifest); no readable
  source fails the run with `source.none`; blocking validation issues fail
  the launch with the issue's code.
- Memory guard integration: source preflight (§8.6), per-experiment
  admission (fail → `memory.limit`, defer → wait), worker-count clamping
  with a logged warning, recycle on RSS growth, and live `memory_updated`.
- Cancellation (§8.4): graceful stops dispatching and cancels queued
  futures; running experiments finish and are kept. Force stop kills
  workers (repeatedly, covering the spawn race window); force-killed
  in-flight experiments count as cancelled.
- Crash/timeout recovery (§8.5): one pool rebuild per crash wave; the run
  aborts with `pool.unstable` beyond the rebuild limit; worker logs and
  tracebacks are forwarded into `run.log`.
- Tests: `tests/runner/test_service.py` (11) with real spawned workers and
  pytest-qt signal collection.

## Deviations

- **`RunnerSettings` instead of `Settings`.** §8.7's `RunRequest.settings:
  Settings` references the Qt settings wrapper that Phase 6 (P5-01)
  delivers; the runner cannot import it (and `Settings` does not exist
  yet). `RunnerSettings` is the runner-facing slice (§16 runner keys);
  P5-01's `Settings` will map onto it. Additive; no existing contract
  changed.
- **`RunRequest.user_blocks_dir` added** (§8.7's sketch omits it): the
  snapshot alone does not know helper `.py` files, but the run's
  `blocks/` copy must contain them or the worker's snapshot hash will not
  match the parent's.
- Two deadlocks found and fixed while testing (documented for review):
  (1) after a graceful cancel the dispatch loop spun forever instead of
  breaking out — the summary was never emitted; (2) a deferred dispatch
  with nothing in flight deadlocked — idle workers hold RSS that never
  frees, so the guard deferred forever; the service now recycles the pool
  once in that state, then dispatches anyway with a logged warning.
- Workspace policy blocks `git switch`; committed directly on `main`.
