## Scope

Implemented `src/pic_utils/runner/service.py` (architecture §8.7):

- `RunnerSettings` (workers, memory ceiling, experiment timeout) and
  `RunRequest` (plus `user_blocks_dir` so the run's `blocks/` copy contains
  the helper files the snapshot hash covers).
- `RunService(QObject)` with `run_started`/`progress`/`result_ready`/
  `run_finished`/`run_failed`/`memory_updated`; the §8.7 sequence (validate
  → run folder + manifest → blocks copy → source load + shared memory →
  plan → dispatch → collect → finalize) runs on a dedicated thread; only
  signal emission touches the GUI thread; one run at a time (a second
  `start()` is a programming error).
- Validation issues block the launch and surface as `run_failed` with the
  issue's code; unreadable sources are skipped with a warning; no readable
  source fails with `source.none`; the source preflight refuses a selection
  that cannot fit (`memory.limit`).
- Memory-guard dispatch: per-experiment estimates, admit/defer/fail,
  worker-count clamping with a logged warning, recycle on RSS growth,
  and one pool rebuild per crash wave (`worker.crashed`, `block.timeout`),
  aborting with `pool.unstable` beyond the rebuild limit.
- Cancellation (§8.4): graceful stops dispatching and cancels queued
  futures, running experiments finish and are kept; force stop kills
  workers (repeatedly, covering the spawn race window) and counts in-flight
  experiments as cancelled. The summary's cancelled count is the exact
  remainder, so completed + failed + cancelled == total.
- Worker logs and tracebacks are forwarded into `run.log` (single writer).
- Tests: `tests/runner/test_service.py` (11) with real spawned workers and
  pytest-qt signal collection.

## Deviations

- **`RunnerSettings` instead of `Settings`.** §8.7's `RunRequest.settings:
  Settings` references the Qt settings wrapper that Phase 6 (P5-01)
  delivers; the runner cannot import it (and it does not exist yet).
  `RunnerSettings` is the runner-facing slice of the §16 runner keys;
  P5-01's `Settings` will map onto it. Additive; no existing contract
  changed.
- **`RunRequest.user_blocks_dir` added** (§8.7's sketch omits it): the
  snapshot alone does not know helper `.py` files, but the run's `blocks/`
  copy must contain them or the worker's snapshot hash will not match the
  parent's.
- Two deadlocks/stalls found and fixed while testing (documented for
  review): (1) after a graceful cancel the dispatch loop spun forever
  instead of breaking out — the summary was never emitted; (2) a deferred
  dispatch with nothing in flight deadlocked — idle workers hold RSS that
  never frees, so the guard deferred forever; the service now recycles the
  pool once in that state, then dispatches anyway with a logged warning.
- Adversarial review (2 passes) fixes: the result/thumbnail write loop
  moved inside `run_experiment`'s try so write failures map to `io.write`
  (§18.2); worker-side `RunError` (e.g. `shm.unavailable`) keeps its own
  stable code instead of being relabeled `block.raised`; `init_worker`
  applies `WorkerInit.log_level` so INFO/DEBUG worker records reach
  `run.log`; the run's `block_snapshot_hash` is computed from the copied
  blocks folder with fresh-state semantics (the app registry's last-good
  hash for a broken user file is not reproducible worker-side); a per-task
  snapshot-hash check in `run_experiment` implements §8.3 step 2.
