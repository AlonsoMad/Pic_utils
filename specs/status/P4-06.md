## Scope

Implemented `tests/runner/test_integration.py` (13 tests) — end-to-end
through the real stack (RunService → SupervisedPool with spawned workers →
worker execution → RunStore/results.jsonl → curation → trash):

- full run: manifest/results.jsonl/curation/run.log/blocks consistency;
  result pixels equal the block output; grid plan experiment counts.
- a raising block fails exactly one experiment and the batch continues
  (`block.raised`); invalid output likewise (`block.invalid_output`).
- worker crash recovery (`worker.crashed`, pool rebuild, batch continues).
- timeout kill (`block.timeout`, the fast experiment survives).
- graceful cancel keeps completed results and the manifest records
  `cancelled`; force cancel kills running experiments.
- trash: discard moves file+thumb into the session trash and records the
  state; restore moves back and clears it.
- shared memory is fully released after a run (POSIX `/dev/shm` check).
- accept/discard updates curation and the canvas accepted index.

## Deviations

- The failure-path tests sweep a `fail` parameter over two experiments
  (one fails, one succeeds) — a single-experiment plan cannot demonstrate
  "the batch continues".
- Two test-side bugs found and fixed while stabilizing: a missing trailing
  comma made `axes` a single `SweepAxis` (the run correctly failed with
  `run.invalid_axis`), and `is_running` is asserted via `waitUntil` because
  the summary signal fires just before the run thread clears the flag.
