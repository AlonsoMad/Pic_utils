## Scope

Shared core utilities every later task builds on, per architecture §18, §2
and plan Phase 1 (P0-03):

- `src/pic_utils/core/errors.py`: the full §18.1 exception hierarchy
  (`PicUtilsError`; `ValidationError.issues`; `BlockError.block/step_id`;
  `InvalidBlockOutput`; `ImageLoadError.path/reason`;
  `ImageTooLargeError.width/height`; `UnsupportedImageError`;
  `MemoryLimitError`; `ExportError`; `CanvasFileError`; `ProjectFileError`;
  `RunError.code`) plus all 12 §18.2 runtime error codes as `Final` string
  constants. `core/` imports nothing from the application layers (§1.3);
  `ValidationError.issues` is typed `Sequence[Any]` (the concrete pipeline
  `Issue` lives in `pipeline/validate.py`, §6.3).
- `src/pic_utils/core/jsonio.py`: `jsonable()` (numpy scalars/arrays, nested
  containers, tuples→lists, clear `TypeError` otherwise),
  `write_json_atomic()` (serialize first, temp file in the same directory,
  fsync, `os.replace`, cleanup on any failure), `read_json()`
  (missing → natural `FileNotFoundError`; corrupt/undecodable → `ValueError`
  naming the file).
- `src/pic_utils/core/paths.py`: streamed SHA-256 `content_hash()`,
  `content_hash_short()` (default 16, canvas asset naming), `safe_name()`
  (NFKD ASCII fold, unsafe-run collapse, edge strip, bounded length,
  `untitled` fallback), `ensure_dir()`. No Qt; settings wiring arrives in
  P5-01.
- `src/pic_utils/logging_setup.py`: stdlib-only `setup_logging(level,
  log_dir)` with a `RotatingFileHandler` (5 MB × 3 backups, §16/§18.3) and a
  console handler, idempotent via marker-handler classes; `run_logger(run_dir)`
  writing `<run_dir>/run.log`, idempotent per directory.
- `src/pic_utils/core/__init__.py`: docstring + re-exports.
- `tests/core/test_utils.py`: 48 behavior tests, including the phase-1 gate
  item — a failed serialization leaves the original file intact AND no temp
  files remain — plus hierarchy/codes, jsonable, hashing, safe-name, and
  logging tests.
