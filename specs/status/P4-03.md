## Scope

Implemented the spawn-safe worker (architecture §8.2-§8.3):

- `src/pic_utils/runner/worker.py`:
  - `WorkerInit` (event queue, blocks dir, run dir, snapshot hash, log
    level) — defined here so the worker never imports the pool.
  - `init_worker`: emits `WorkerReady`, installs a queue log handler (the
    parent writes `run.log`, §18.3), adds the run's copied blocks folder to
    `sys.path`, builds the block snapshot from built-ins + copied user
    blocks, and verifies the run's `block_snapshot_hash`; a mismatch fails
    every task with `block.snapshot_mismatch`.
  - `run_experiment`: emits `ExperimentStarted` (crash attribution, §8.5),
    attaches source/second shared memory into private arrays, executes the
    pipeline, writes one PNG per layer plus a 256 px PNG thumbnail (atomic
    saves, thumbnails from the in-memory result, §19.2), and returns a
    small outcome — no image data crosses back (§8.3).
  - Error mapping per §18.2: `InvalidBlockOutput` → `block.invalid_output`,
    any other exception (including plain `RuntimeError`/`ZeroDivisionError`
    from block code) → `block.raised`, `ExportError` while writing →
    `io.write`. Tracebacks go to the run log via the queue; one-line
    messages in the outcome. The batch continues (FR-RUN-06, FR-BLK-10).
- Tests: `tests/runner/test_worker.py` (10): ready/started events, single
  and multi-layer results, thumbnail bound, raising block, plain exception,
  invalid output, snapshot mismatch, outcome size, and a subprocess test
  proving `pic_utils.runner.worker` imports without PySide6 (§1.3).

## Deviations

- **`_WorkerSnapshot` structural mirror.** §8.2 says the worker "builds a
  `BlockSnapshot`", but `BlockSnapshot` lives in `blocks/registry.py`,
  which imports `PySide6.QtCore` (P2-02), and §1.3 forbids Qt in worker
  code. The two requirements cannot both hold as written. Resolution within
  this task's ownership: `worker.py` defines `_WorkerSnapshot`, a
  field-for-field mirror (`defs`, `hash`, `get`, `__contains__`, `__iter__`,
  `__len__`), and duplicates `BlockRegistry._snapshot_hash`'s payload so
  the worker can verify the run's hash without importing Qt. The one
  `# type: ignore[arg-type]` at the `execute_pipeline` call site is
  documented in place. Drift fails loud (`block.snapshot_mismatch` on every
  run), not silent. **Recommended follow-up (CC):** move `BlockSnapshot`
  and the snapshot-hash payload into a Qt-free module (e.g.
  `blocks/snapshot.py`) with `registry.py` re-exporting, so the worker can
  use the real class. Not done here because `registry.py` is P2-02's file.
- Workspace policy blocks `git switch`; committed directly on `main`.

## BUG-1 (found during this task, file not owned)

`src/pic_utils/core/errors.py` (P0-03) defines exceptions as frozen
dataclasses. A frozen dataclass overrides `__setattr__` for **all** fields,
including `__traceback__`, so `contextlib._GeneratorContextManager.__exit__`
(`exc.__traceback__ = traceback`, contextlib.py:191 in CPython 3.12) raises
`dataclasses.FrozenInstanceError` whenever a typed exception
(`RunError`, `BlockError`, `InvalidBlockOutput`, `ImageLoadError`, …)
propagates out of a `@contextmanager`-based `with` block — masking the real
error. Reproduced:

```
$ python -c "..."
dataclasses.FrozenInstanceError: cannot assign to field '__traceback__'
```

Impact: any app/test code that lets a typed exception cross a
`@contextmanager` boundary sees `FrozenInstanceError` instead. Not fixed
here (`errors.py` is P0-03's file; a fix is a `CC-ERR` change). Suggested
fix: make the exception dataclasses non-frozen (drop `frozen=True`, keep
`eq=False`), or give them plain-class `__setattr__` for dunder fields.
