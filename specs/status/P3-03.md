## Scope

Added `src/pic_utils/pipeline/execute.py` implementing architecture §6.2:

- `PipelineOutput(layers)` and `execute_pipeline(pipeline, snapshot, source,
  second, experiment)`.
- Chain input binding, second-image binding for extra image inputs, mask side
  inputs from `mask_bindings`, bypass, and LAYERS as a terminal step.
- Mask blocks store their output under the step id and do not advance the
  image chain.
- Alpha propagation per §3.1: a same-size output with `alpha is None`
  inherits the chain input's alpha; a geometry change keeps the block's own
  (possibly absent) alpha; an explicit opaque alpha is preserved.
- Per-step seed resolution: experiment override → pipeline value → derived
  `derive_seed(experiment.seed, "step", step.id)`.
- Scalar params resolve experiment override → pipeline step value → block
  default (the planner only stores overrides).
- Output validation per §5.6 raising `InvalidBlockOutput`
  (`block.invalid_output`): type, mask shape, binary mask values, layer count
  and layer item type. Block exceptions propagate unchanged so the runner can
  record `block.raised`.

## Deviations

- Workspace policy blocks `git switch`; committed directly on `main`.
- `InvalidBlockOutput` is a frozen dataclass, so `BaseException.add_note`
  cannot be used; the specific violation is chained as the exception cause
  (`raise InvalidBlockOutput(...) from ValueError(reason)`), keeping the
  stable type while preserving the diagnostic.
- Scalar parameters fall back to the step's stored value when the experiment
  spec does not override them, matching the §7.2 rule that unswept
  parameters "keep the pipeline value".
