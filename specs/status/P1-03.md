## Scope

Implemented the only file-format boundary per architecture §4 and
implementation-plan §8 (P1-03):

- `src/pic_utils/io/formats.py` (new): `MAX_PIXELS = 48_000_000`, the
  PNG/JPEG/TIFF extension table, `format_for_path`, `is_supported_path`.
- `src/pic_utils/io/loader.py` (new): `ImageInfo`, `probe_image`,
  `load_image`, `load_mask`. Loads apply EXIF orientation, normalize
  grayscale/palette/CMYK/RGBA to the canonical `Image`, reject 16-bit and
  > 48 MP inputs with typed errors, and warn on non-sRGB ICC profiles.
- `src/pic_utils/io/saver.py` (new): `save_image` (PNG/JPEG/TIFF, atomic
  temp-file + `os.replace`, JPEG alpha flattened onto white, TIFF LZW,
  sRGB ICC embedded) and `save_mask` (atomic grayscale PNG).
- `src/pic_utils/io/__init__.py` (new): re-exports the public I/O API.
- `tests/io/test_io.py` (new): 20 tests covering PNG/TIFF RGB/RGBA
  round-trips, JPEG, probe metadata, grayscale, EXIF orientation and
  non-re-emission, 16-bit rejection, > 48 MP rejection, missing files,
  sRGB ICC in all three formats, mask round-trip, atomic-save failure,
  unsupported extensions, invalid JPEG quality, and non-PNG masks.

## Deviations

- Workspace policy blocks `git switch`; committed directly on `main`.
- 16-bit input raises `UnsupportedImageError` whose reason starts with
  `image.16bit:`. `image.16bit` is not one of the §18.2 runtime codes, so
  no new code constant was added; the reason carries the UI-facing code.
  Oversized input raises `ImageTooLargeError` with the dimensions.
- `save_image` raises `ExportError` for write failures and `ValueError`
  for an unsupported destination extension or out-of-range quality.
- PNG uses `compress_level=3` (the results path); the export path can
  revisit the level when P6-03 lands.
