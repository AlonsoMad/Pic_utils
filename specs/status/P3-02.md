## Scope

Added `src/pic_utils/pipeline/validate.py` implementing architecture §6.3:

- `Issue` (severity/code/message/step_id/param), `is_blocking()`, and
  `unreadable_source_issue()`.

  sources_available)` covering every code in the §6.3 table:
  `pipeline.empty`, `step.unknown_block`, `step.duplicate_id`,

## Deviations

- Workspace policy blocks `git switch`; committed directly on `main`.
- A binding whose target step id does not exist is reported as
  `mask.unbound` (with the unknown target named in the message). The §6.3
  table has no dedicated code for a dangling binding, and adding one would
  be a contract change.
- `step.no_output` is evaluated over non-bypassed steps only, matching the
  executor's "last non-bypassed step" rule.
- `validate_run_config` takes an optional `source_count` (default 1) because
  the architecture signature cannot compute the total experiment count
  without it; the default keeps the documented call shape valid.
