## Scope

Implemented the three mask blocks per architecture §5.7 and
implementation-plan §8 (P2-04):

- `src/pic_utils/blocks/builtin/masks.py` (new):
  - `channel_mask` (`MASK`): selects by R/G/B or Rec. 709 luminance in
    `low..high`; soft masks carry the channel/luminance value inside the
    range, binary masks are 255/0.
  - `brightness_mask` (`MASK`): selects luminance `<= threshold`;
    `auto=True` replaces the threshold with the median luminance from
    `find_channel_percentiles`; soft masks carry luminance.
  - `color_range_mask` (`MASK`): per-channel ranges with `strict`
    (all channels) or loose (any channel); soft masks carry the mean RGB
    value inside the selection.
  - All three support `soft` and `invert`.
- `tests/blocks/test_masks.py` (new): 14 tests covering each channel,
  luminance, soft values, binary/inverted output, empty ranges, auto
  median, strict/loose color ranges, and read-only masks.

## Deviations

- Workspace policy blocks `git switch`; committed directly on `main`.
- Soft-mask semantics are defined here because the architecture only says
  "binary or soft": the mask carries the underlying channel/luminance/mean
  intensity inside the selection and 0 outside; `invert` complements the
  result (`255 - mask`).
- `brightness_mask` uses `<= threshold` (so the default 255 selects every
  pixel) and the median (50th percentile) for `auto`.
- `color_range_mask` soft values use the mean of the three channels; the
  condition itself is per-channel and independent of the soft value.
