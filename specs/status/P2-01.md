## Scope

Implemented the public block authoring API per architecture §5.1-§5.3 and
implementation-plan §8 (P2-01):

- `src/pic_utils/blocks/api.py` (new): `OutputKind`, `ParamKind`,
  `IntRange`, `FloatRange`, `Choice`, `Color`, `Seed`, `ParamDef`,
  `BlockDef`, `BlockLoadError`, `BLOCK_API_VERSION`, and the `block`
  decorator.
- The decorator resolves `Annotated` hints with
  `typing.get_type_hints(..., include_extras=True)`, classifies every
  parameter kind (`int`/`IntRange`, `float`/`FloatRange`,
  `Choice` for str/int/float, `bool`, `str`/`Color`, `int | None`/`Seed`,
  `Image`, `Mask`, `Mask | None`), validates defaults against their specs,
  collects `image_inputs`/`mask_inputs` in signature order, and checks the
  return annotation against the declared output kind.
- Invalid signatures raise `BlockLoadError`: missing scalar default,
  `*args`/`**kwargs`, positional-only parameters, missing annotations,
  bare `int`/`str`, `Image` with a default, optional mask with a non-None
  default, `int | None` without `Seed`, mismatched metadata, choice option
  type mismatch, out-of-range default, invalid `Color` default, invalid
  `Seed` default, and output/return-annotation mismatch.
- `src/pic_utils/blocks/__init__.py` (new): re-exports the public API. It
  deliberately does not import the registry, so importing the API has no
  discovery side effects.
- `tests/blocks/test_api.py` (new): 27 tests covering metadata, all
  parameter kinds, input splitting, parameter order, immutability, and
  every rejection path.

## Deviations

- Workspace policy blocks `git switch`; committed directly on `main`.
- `BlockLoadError` lives in `blocks/api.py` rather than `core/errors.py`.
  The architecture names it but §18.1 does not include it; adding it to
  `core/errors.py` would be a contract change outside P2-01's ownership.
  It is a subclass of `PicUtilsError`, so callers can still catch the base.
- The decorator stores the base annotation (e.g. `int`, `int | None`,
  `Image`) in `ParamDef.annotation`; the metadata instance lives in
  `ParamDef.spec`. This keeps the executor/UI from re-parsing `Annotated`.
- `Choice`/`IntRange`/`FloatRange` validate their own invariants at
  construction (non-empty/unique options, labels length, min <= max,
  positive step).
